# Trigger Bot

Telegram-бот для управления пользовательскими триггерами в чатах. Позволяет пользователям задавать ключевые фразы и соответствующие ответы (текст, изображения, стикеры и т.д.).

## Возможности

### Триггеры
*   **Создание триггеров**: Настройка триггеров с текстом, фото, стикерами, анимацией и т.д.
*   **Типы совпадений**: Точное совпадение, Содержит, Регулярное выражение.
*   **Контроль доступа**: Настройка того, кто может добавлять триггеры (все или только администраторы).
*   **Управление**: Список, удаление и управление триггерами через команды и инлайн-интерфейс.

### Модерация
*   **AI-модерация**: Автоматическая проверка контента через inference-сервер (NSFW-классификатор + мультимодальная LLM).
*   **Система варнов**: Предупреждения пользователей с настраиваемым лимитом.
*   **Мут/бан**: Ограничение и блокировка пользователей.
*   **Канал модерации**: Уведомления о нарушениях в отдельный чат.

### Капча
*   **Защита от ботов**: Проверка новых участников при входе в чат.
*   **Типы капчи**: Различные варианты проверки (текст, кнопки и др.).
*   **Автоудаление**: Кик пользователей, не прошедших проверку.

### Приветствия
*   **Кастомные сообщения**: Настраиваемые приветствия для новых участников.
*   **Шаблоны**: Переменные для имени пользователя, названия чата и т.д.

### Глобальный бан (GBan)
*   **Синхронизация**: Загрузка списка спамеров из внешнего источника (lols.bot).
*   **Автобан**: Автоматическая блокировка пользователей из списка.
*   **Включение/выключение**: Настройка для каждого чата отдельно.

### Система доверия (Trust)
*   **Уровни доверия**: Отслеживание репутации пользователей.
*   **История**: Журнал изменений уровня доверия.

### Прочее
*   **Интернационализация**: Расширяемая система локализации с автообнаружением языков.
*   **Кэширование**: Высокая производительность благодаря кэшированию Valkey (Redis).
*   **Переменные чата**: Хранение пользовательских переменных для каждого чата.
*   **Часовые пояса**: Настройка временной зоны для чата.
*   **Статистика**: Сбор и отображение статистики использования.

### Запуск

```bash
cd frontend
npm install
npm run dev
```

### 2. Запуск inference-сервера (на GPU-машине)

На сервере с NVIDIA GPU:

```bash
# Настроить .env для GPU-сервера
cat > .env << EOF
INFERENCE_IMAGE=registry.gitlab.fenicu.com/trigger/trigger/inference:latest
INFERENCE_PORT=8100
INFERENCE_API_KEY=your-secret-key
OLLAMA_MODEL=qwen2.5-vl:7b
EOF

# Запустить inference + ollama
docker compose -f compose.gpu.yml up -d

# Загрузить LLM-модель (при первом запуске)
docker compose -f compose.gpu.yml exec ollama ollama pull qwen2.5-vl:7b
```

Inference-сервер включает:
- **NSFW-классификатор** (`falconsai/nsfw_image_detection`) — детекция порно (~50ms, CPU)
- **Мультимодальная LLM** (`qwen2.5-vl:7b` через Ollama) — детекция наркотиков и скама

### 3. Запуск бота

```bash
docker compose up -d --build
```

## Использование

### Команды

*   `/trigger <key>` - Запустить мастер создания триггера для указанной ключевой фразы.
*   `/triggers` - Показать список всех триггеров в текущем чате.
*   `/del <key>` - Удалить конкретный триггер по его ключевой фразе.
*   `/lang` - Изменить язык бота.
*   `/settings` - Открыть меню настроек (только для администраторов).

### Настройки

*   **Admins Only Add**: Переключить режим, когда только администраторы могут создавать триггеры.
*   **Clear All Triggers**: Удалить все триггеры в чате (требуется подтверждение).

## Локализация (i18n)

Бот использует [fluentogram](https://github.com/Arustinal/fluentogram) для интернационализации. Переводы хранятся в `.ftl` файлах формата [Project Fluent](https://projectfluent.org/).

### Структура

```
locales/
├── en/
│   └── messages.ftl    # Английский
└── ru/
    └── messages.ftl    # Русский (основной)
```

Локали обнаруживаются автоматически: любая директория в `locales/` с файлом `messages.ftl` регистрируется как доступный язык. Кнопки выбора языка в `/lang` генерируются динамически.

### Добавление нового языка

1. Скопируйте шаблон (например, из английской локали):

```bash
cp -r locales/en locales/uk
```

2. Переведите все ключи в `locales/uk/messages.ftl`. Обязательно укажите название языка:

```fluent
lang-display-name = 🇺🇦 Українська
```

3. Перегенерируйте стабы (см. ниже) и перезапустите бота. Новый язык автоматически появится в меню `/lang`.

### Извлечение ключей из кода

Проект использует [FTL-Extract](https://pypi.org/project/FTL-Extract/) для автоматического извлечения ключей переводов из исходного кода. Это гарантирует синхронизацию между кодом и `.ftl` файлами.

```bash
make extract
```

Команда сканирует `app/`, находит все вызовы `i18n.xxx()`, и обновляет `.ftl` файлы:
- Новые ключи добавляются с placeholder-значениями
- Неиспользуемые ключи комментируются

> **Внимание:** ключи с пользовательскими функциями (например, `DATETIME($date)`) могут быть пересозданы некорректно. После извлечения проверьте их вручную.

### Типизированные стабы

Файл `fluentogram.pyi` в корне проекта обеспечивает автодополнение и проверку типов для ключей переводов. Вместо строковых ключей (`i18n.get("key")`) используется dot-нотация: `i18n.trigger.edit.title()`.

**Перегенерация стабов** (после изменения `.ftl` файлов):

```bash
uv run fluentogram -d locales/ru -o fluentogram.pyi
```

**Watch-режим** (автоматическая перегенерация при изменениях):

```bash
uv run fluentogram -d locales/ru -o fluentogram.pyi -w true
```

### Правила именования ключей

При добавлении новых ключей в `.ftl` файлы необходимо соблюдать ограничения генератора стабов:

*   **Нельзя** использовать зарезервированные слова Python как сегменты ключа (`not`, `del`, `match`, `class`, `def`, `return`, `import`, `from`, `is`, `in`, `or`, `and`, `async`, `await` и др.)
*   **Нельзя** начинать сегмент с цифры (`1h`, `10m`)
*   Сегменты ключа разделяются дефисом: `trigger-edit-title` → `i18n.trigger.edit.title()`
*   Параметры задаются через `{ $param }` в `.ftl` и передаются как keyword-аргументы: `i18n.trigger.added(trigger_key="hello")`
