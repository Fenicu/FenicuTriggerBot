# Trigger Bot

Многофункциональный Telegram-бот для управления чатами. Триггеры, модерация, капча, система репутации с тегами, webapp-настройки, приветствия с редактором и многое другое.

[Руководство пользователя](https://telegra.ph/Trigger-Bot--Rukovodstvo-polzovatelya-04-05) | [@FenicuTriggerBot](https://t.me/FenicuTriggerBot)

## Возможности

### Триггеры
*   **Создание триггеров**: Текст, фото, видео, стикеры, GIF, документы — любой тип контента.
*   **Типы совпадений**: Точное совпадение, Содержит, Регулярное выражение. Сравнение унифицировано через NFKC + casefold — `ﬁle` ↔ `file`, `Ｒ` ↔ `R`, `straße` ↔ `STRASSE`.
*   **Создание в ЛС (без раскрытия контента)**: `/newtrigger` в группе или в ЛС запускает wizard в личных сообщениях — выбор чата, контент, ключ, флаги кнопками, предпросмотр, сохранение. Сессия живёт 60 мин, `/cancel` отменяет на любом шаге.
*   **Шаблоны (Jinja2)**: Динамические ответы с переменными `{{ user.mention }}`, `{{ chat.title }}`, `{{ date }}`, `{{ vars.* }}`.
*   **Контроль доступа**: Для всех / только админов / только владельца. Настройка per-триггер.
*   **Переменные чата**: `/setvar`, `/delvar`, `/vars` — хранение данных для использования в шаблонах.

### Модерация
*   **Команды**: `/ban`, `/unban`, `/mute`, `/unmute`, `/warn`, `/warns` с поддержкой времени и причины.
*   **Система варнов**: Настраиваемый лимит, автоматическое наказание (бан/мут) при превышении.
*   **AI-модерация**: Автоматическая проверка контента триггеров через [trigger-inference](https://gitlab.fenicu.com/trigger/trigger-inference) — Gemma 4 E4B GGUF через llama.cpp (6 категорий: Drugs, Porn, Scam, Violence, PersonalData, Safe).
*   **Голосовая модерация**: Голосовые (`voice`) и видеокружки (`video_note`) транскрибируются ASR-сервисом (`ASR_URL`, faster-whisper); транскрипт уходит в AI-модерацию и отображается в карточке алерта. Музыка (`audio`) не модерируется.
*   **Медиа в карточках алертов**: Фото, видео, GIF, аудио и голосовые встраиваются прямо в rich-карточку модерации; документы, стикеры и видеокружки отправляются отдельным сообщением. Транскрипт и цепочка редиректов свёрнуты в раскрываемые блоки.
*   **Глобальный бан**: Синхронизация со спам-листами, автобан при входе.

### Капча
*   **Emoji-капча**: Сетка 4×4 эмодзи с цветовой дифференциацией, прямо в чате.
*   **WebApp-капча**: Проверка через мини-приложение в ЛС бота.
*   **Эфемерные ответы**: Сетка видна только проверяемому юзеру; если эфемерная отправка недоступна (бот не админ чата и т.п.) — обычная капча с автоудалением, как раньше.
*   **Guard-bot на заявках на вступление**: При включённой капче чат может назначить бота обработчиком заявок (guard-bot) в настройках. Заявки с query_id обрабатываются автоматически: глобально забанённые отклоняются сразу, доверенные и прошедшие капчу ранее одобряются, остальные проходят через WebApp-капчу. При таймауте заявка отклоняется и юзер получает бан на срок «бан за провал капчи». Заявки без query_id остаются в руках администраторов.
*   **Настройки**: Таймаут (1-10 мин), попытки (1-10), длительность бана за провал.

### Приветствия
*   **Команда `/welcome`**: Быстрая установка из чата (ответом на сообщение).
*   **Webapp-редактор**: Полноценный редактор с форматированием, загрузкой медиа (фото/видео/GIF), конструктором URL-кнопок, шаблонными переменными и live-превью в стиле Telegram.
*   **Автоудаление**: Настраиваемый таймер.

### Репутация и теги
*   **Автоматические теги**: Бот ставит тег рядом с именем через Telegram API (`setChatMemberTag`).
*   **Система очков**: Реакции (×3), ответы (×2), сообщения (×1) с антифлуд-защитой.
*   **5 уровней**: Пресеты (нейтральный/игровой/числовой) или кастомные названия.
*   **Команды**: `/status` (прогресс), `/tag` (ручной тег от админа), `/deltag`.
*   **Настройка**: Пороги, веса, антифлуд-лимиты — через webapp.

### Автоудаление сервисных сообщений
*   **Типы сообщений**: Капча (таймаут/успех), модерация (/ban, /mute, /kick, /warn), глобальный бан, приветствия.
*   **Индивидуальные настройки**: Вкл/выкл и задержка (1–3600 сек) для каждого типа отдельно.
*   **Секция в webapp**: Настройка через веб-интерфейс в разделе «Автоудаление сообщений».

### Webapp-настройки
*   **Веб-интерфейс**: Все настройки чата через Telegram WebApp — 8 секций.
*   **Доступ**: Для админов чата (через deep link) и BOT_ADMIN (через админ-панель).
*   **Вход через браузер**: Telegram OIDC авторизация для доступа вне Telegram.
*   **Per-section access control**: Владелец может заблокировать секции для обычных админов.
*   **Аудит лог**: Запись всех изменений (кто, что, когда). Команда `/auditlog` и секция в webapp.

### Прочее
*   **Персональные ответы команд**: Команды `/status` (репутация), `/warns` (список варнов), `/vars` (переменные), `/auditlog` (лог действий) видны только их автору — отправляются как эфемерные сообщения в группе и помечены в списке команд как личные.
*   **Интернационализация**: Русский и английский, автообнаружение языков, расширяемо.
*   **Админ-панель**: Webapp для BOT_ADMIN — управление чатами, пользователями, триггерами, статистика.
*   **Мониторинг ошибок**: Опциональная интеграция с GlitchTip/Sentry (`SENTRY_DSN`).
*   **Кэширование**: Valkey (Redis) для производительности.
*   **CI/CD**: Автосборка и деплой через GitLab CI по тегу.

## Веб-интерфейс (Frontend)

Два веб-интерфейса в одном React-приложении (`frontend/`):

### Админ-панель (для BOT_ADMIN)
Доступ: команда `/admin` в ЛС бота.
*   **Dashboard**: Статистика — пользователи, чаты, триггеры, графики активности.
*   **Чаты**: Список чатов, детали, настройки, триггеры, пользователи, бан/leave.
*   **Пользователи**: Просмотр, роли (trust/moderator), баны.
*   **Триггеры**: Все триггеры, модерация, одобрение/отклонение.

### Webapp настроек (для админов чата)
Доступ: кнопка «Открыть настройки» в `/settings` → deep link в ЛС бота.
*   **ChatSettingsForm**: 8 секций настроек (общее, капча, модерация, триггеры, теги, приветствие, автоудаление, прочее).
*   **WelcomeEditor**: Редактор приветствий (форматирование, медиа, URL-кнопки, live-превью).
*   **AuditLog**: История изменений настроек.
*   **Section locks**: Блокировка секций владельцем чата.

### Технологии

*   React + TypeScript
*   Vite
*   TailwindCSS

## Использование

### Команды

#### Триггеры
*   `/add <ключ>` — создать триггер (ответом на сообщение). Флаги: `-t` (шаблон), `-c` (регистр), `-m contains|regexp`, `-a admins|owner`
*   `/del <ключ>` — удалить триггер
*   `/triggers` — список триггеров чата

#### Переменные
*   `/setvar <ключ> <значение>` — создать/обновить переменную чата
*   `/delvar <ключ>` — удалить переменную
*   `/vars` — список переменных

#### Модерация
*   `/ban [время] [причина]` — забанить (ответом)
*   `/unban` — разбанить
*   `/mute [время] [причина]` — заглушить
*   `/unmute` — снять мут
*   `/warn [причина]` — предупреждение
*   `/warns` — список предупреждений

#### Приветствия
*   `/welcome set [таймаут]` — установить приветствие (ответом)
*   `/welcome delete` — отключить
*   `/welcome test` — предпросмотр

#### Репутация
*   `/status` — очки, уровень, прогресс, позиция в рейтинге
*   `/tag <текст>` — ручной тег (ответом, для админов)
*   `/deltag` — снять ручной тег (ответом)

#### Настройки и прочее
*   `/settings` — панель настроек (inline-кнопки + webapp)
*   `/lang` — смена языка
*   `/auditlog` — лог изменений настроек
*   `/admin` — админ-панель (ЛС, BOT_ADMIN)
*   `/trust <user>` — доверенный пользователь (модератор бота)
*   `/add_mod <user>` — назначить модератора бота

## Локализация (i18n)

Бот использует [fluentogram](https://github.com/Arustinal/fluentogram) для интернационализации. Переводы хранятся в `.ftl` файлах формата [Project Fluent](https://projectfluent.org/).

### Структура

```
locales/
├── en/
│   └── messages.ftl    # Английский
└── ru/
    └── messages.ftl    # Русский (основной)
```

Локали обнаруживаются автоматически: любая директория в `locales/` с файлом `messages.ftl` регистрируется как доступный язык. Кнопки выбора языка в `/lang` генерируются динамически.

### Добавление нового языка

1. Скопируйте шаблон (например, из английской локали):

```bash
cp -r locales/en locales/uk
```

2. Переведите все ключи в `locales/uk/messages.ftl`. Обязательно укажите название языка:

```fluent
lang-display-name = 🇺🇦 Українська
```

3. Перегенерируйте стабы (см. ниже) и перезапустите бота. Новый язык автоматически появится в меню `/lang`.

### Извлечение ключей из кода

Проект использует [FTL-Extract](https://pypi.org/project/FTL-Extract/) для автоматического извлечения ключей переводов из исходного кода. Это гарантирует синхронизацию между кодом и `.ftl` файлами.

```bash
make extract
```

Команда сканирует `app/`, находит все вызовы `i18n.xxx()`, и обновляет `.ftl` файлы:
- Новые ключи добавляются с placeholder-значениями
- Неиспользуемые ключи комментируются

> **Внимание:** ключи с пользовательскими функциями (например, `DATETIME($date)`) могут быть пересозданы некорректно. После извлечения проверьте их вручную.

### Типизированные стабы

Файл `fluentogram.pyi` в корне проекта обеспечивает автодополнение и проверку типов для ключей переводов. Вместо строковых ключей (`i18n.get("key")`) используется dot-нотация: `i18n.trigger.edit.title()`.

**Перегенерация стабов** (после изменения `.ftl` файлов):

```bash
uv run fluentogram -d locales/ru -o fluentogram.pyi
```

**Watch-режим** (автоматическая перегенерация при изменениях):

```bash
uv run fluentogram -d locales/ru -o fluentogram.pyi -w true
```

### Правила именования ключей

При добавлении новых ключей в `.ftl` файлы необходимо соблюдать ограничения генератора стабов:

*   **Нельзя** использовать зарезервированные слова Python как сегменты ключа (`not`, `del`, `match`, `class`, `def`, `return`, `import`, `from`, `is`, `in`, `or`, `and`, `async`, `await` и др.)
*   **Нельзя** начинать сегмент с цифры (`1h`, `10m`)
*   Сегменты ключа разделяются дефисом: `trigger-edit-title` → `i18n.trigger.edit.title()`
*   Параметры задаются через `{ $param }` в `.ftl` и передаются как keyword-аргументы: `i18n.trigger.added(trigger_key="hello")`
